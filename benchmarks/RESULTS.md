## Command lines

```
php benchmarks/run.php --scenario=transport-warm --count=20000 --server-delay-ms=0 --repeat=5 --json --out=benchmarks/results/transport-warm-d0.json
```

How to read the tables: *requests per run* are completed exchanges seen by the client; *req/s* is requests divided by wall time of the run (median and range over the repeated runs); latency columns are the median over runs of the per-request duration reported by the transport (hand-over to libcurl until completion, so it contains the mock's artificial delay and any queueing inside libcurl); *peak MiB over start* is `memory_get_peak_usage()` after a peak reset minus usage at the start; *growth* is usage at the end minus at the start, raw and after `gc_collect_cycles()`; *cpu ms/req* is user+system CPU of the PHP process per request (the Node server's CPU is not included); *connections* and *max concurrent streams* are counted by the mock server, not by the client.

## What these numbers do and do not show

They show, for one machine and one PHP/libcurl/Node combination, how much CPU and memory this package's PHP code spends per request when the peer is a fast local HTTP/2 server with a configurable fixed delay, how throughput reacts to the window and connection settings, whether memory stays flat for large lazy batches, and how the pool registry bounds connections and file descriptors.

They do **not** show:

- anything about Apple APNs or Google FCM: no real provider was contacted, no real credentials were used, and real providers add network latency, rate limiting, TLS session behaviour, per-connection stream limits and server-side throttling that the mock does not model;
- throughput on a different machine, a different libcurl or a different PHP build; the Node mock server shares the CPU with the PHP process, so at zero delay the server may limit the measured rate as much as the client does;
- the cost of persisting results, queues, Laravel service resolution, or real token signing beyond the first token (tokens are cached for the run);
- latency under real network conditions: latency columns contain the mock's artificial delay plus loopback and scheduling noise;
- a verdict on any other library beyond the situations listed in the comparison (one library version, one configuration, written down above).
